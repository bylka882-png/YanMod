# YanMod — формат `info.toml`

Инструкция для авторов каталога и для себя. Кратко: один мод (или одна сборка) —
одна папка с файлом `info.toml`. Всё остальное — `README.md`, `changelog.md` и
изображения — лежит рядом.

Готовый пример со всеми полями: `пример.toml`.

---

## 1. Где лежит файл

```
YanMod/
├─ build/
│  └─ ChristmasPartyMod/
│     ├─ 1.0.0/
│     │  ├─ info.toml
│     │  ├─ 1.webp
│     │  └─ 2.webp
│     ├─ README.md
│     └─ changelog.md
├─ mod/
├─ PM/
├─ TR/
├─ ML/
├─ Plugins/
├─ Translate/
└─ index.toml
```

- Верхняя папка — раздел: `build`, `mod`, `PM`, `TR`, `ML`, `Plugins`,
  `Translate`. Она подсказывает тип, но настоящий тип — поле `type` в файле.
- Вторая папка — мод. Имя свободное, читаемое, в каталоге не используется.
- Третья папка — версия. Тоже свободная.
- **`info.toml` важнее пути.** Если имя папки расходится с полями `id`,
  `mod_version`, `type`, каталог верит файлу.
- Одинаковый `id` в разных папках = версии одного мода. Они собираются в одну
  карточку и сортируются по `mod_version`.
- `README.md` и `changelog.md` — в папке мода, общие для всех версий. Регистр
  имени не важен: `readme.md` тоже подойдёт.
- Изображения — в папке версии (см. раздел 8).

## 2. Общие правила TOML

Это важно прочитать целиком: 90 % ошибок в манифестах — из этого раздела.

### Секции и ключи

- Секция пишется в квадратных скобках: `[info]`. Все ключи после неё относятся
  к ней.
- Ключи **регистрозависимы**: `name` и `Name` — разные ключи. Пиши ровно так,
  как в этой инструкции.
- Дубликат ключа в одной секции — ошибка. Дубликат секции — ошибка.
- Порядок секций любой, но придерживайся порядка из примера: так проще читать.

### Строки

- Обычная строка — в двойных кавычках: `name = "Christmas Party Mod"`.
- Обратный слэш в двойных кавычках — **спецсимвол**. Поэтому в путях он
  удваивается:

  ```toml
  config = "BepInEx\\config\\BepInEx.cfg"
  ```

  Одинарный `\c` даст ошибку разбора: `invalid escape sequence`.
- Литеральная строка — в одинарных кавычках, внутри ничего не экранируется:

  ```toml
  config = 'BepInEx\config\BepInEx.cfg'
  ```

  Для путей это удобнее. Оба варианта допустимы, но не смешивай в одном файле.
- Кавычки внутри строки: в двойных строках `\"`, в одинарных — просто `"`.
- Строка не переносится на новую строку. Длинное описание — одной строкой.
- `true` и `false` — без кавычек, это логические значения. `"true"` — строка.

### Числа

- Без кавычек: `size = 1939865600`.
- `size = "1939865600"` — ошибка типа, каталог не примет.
- Разделители разрядов можно: `size = 1_939_865_600`.

### Массивы

- Одной строкой: `tags = ["christmas", "party"]`.
- Или по элементу на строку, с запятой после последнего:

  ```toml
  tags = [
      "christmas",
      "party",
  ]
  ```

- Пустой массив: `tags = []`.

### Inline-таблицы

Используются в `installed` и `dependencies`. Каждая — **одной строкой**,
TOML 1.0 не разрешает переносить её содержимое:

```toml
dependencies = [
    { id = "posemod", v = "5" },
]
```

Не так:

```toml
dependencies = [
    {
        id = "posemod",
    },
]
```

### Комментарии

- `#` до конца строки. Комментарии не влияют на каталог, пиши смело.
- Комментарий после значения — нормально: `id = "CPM" # сборка`.

## 3. `[info]`

| Поле | Тип | Обязательно | Что это |
| --- | --- | --- | --- |
| `id` | строка | да | Уникальный ключ мода. Без пробелов и `;`. Регистр не важен. Совпадает с именем архива. |
| `name` | строка | да | Отображаемое имя. |
| `author` | строка | да | Автор. |
| `type` | строка | да | Одно из: `PM`, `Build`, `TR`, `ML`, `Mod`, `Plugin`, `Translate`. |
| `game_versions` | строка | нет | Совместимость. Пусто = неизвестно. |
| `mod_version` | строка | да | Версия мода. Именно она показывается и сравнивается. |
| `tags` | массив строк | нет | До 5 тегов, латиница, нижний регистр. |

### `id`

- Придумывает владелец каталога, не автор мода.
- Только латиница, цифры, `_`, `-`. Без пробелов, точек и `;`.
- Одинаковый `id` = версии одного мода.
- Сравнение без учёта регистра: `CPM` и `cpm` — один мод.

### `type`

Только одно значение. Мод не может быть одновременно `Mod` и `TR`: выбери
основной раздел.

- `Mod` — обычные моды.
- `Build` — готовые сборки игры.
- `PM` — Pose Mod.
- `TR` — текстуры.
- `ML` — загрузчики (BepInEx, PoseMod).
- `Plugin` — плагины BepInEx.
- `Translate` — переводы.

### `game_versions`

Одна строка, один диапазон. Пустая строка = совместимость неизвестна.

| Запись | Смысл |
| --- | --- |
| `U20` | сборка на Unity 2020 |
| `U4-U6` | от Unity 4 до Unity 6 |
| `>=U17` | Unity 2017 и новее |
| `<=U20` | Unity 2020 и старее |
| `2021.02.01` | конкретная сборка игры |
| `2021.02.01-2021.10.01` | период сборок |
| пусто `""` | неизвестно |

Правила:

- Только один оператор и один диапазон на строку. `>=U17` и `<=U20`
  одновременно не записать.
- Пробелы не ставятся: `>=U17`, а не `>= U17`.
- Нераспознанное значение не скрывает мод: карточка показывает
  «совместимость неизвестна».

### `tags`

- До 5 штук.
- Только латиница, нижний регистр: `christmas`, не `Christmas`.
- Пробелов нет, вместо них `-`: `social-challenge`.
- Тег нужен для общего поиска. Не дублируй в нём название мода.

## 4. `[credits]`

Ссылки автора. Все поля необязательные: пустые строки просто не выводятся.

| Поле | Пример |
| --- | --- |
| `boosty` | `https://boosty.to/author` |
| `discord` | `https://discord.gg/invite` |
| `github` | `https://github.com/author` |
| `itchio` | `https://author.itch.io` |
| `patreon` | `https://patreon.com/author` |
| `telegram` | `https://t.me/author` |
| `youtube` | `https://www.youtube.com/@author` |

- Полная ссылка со схемой `https://`. Без схемы каталог её не откроет.
- Если ссылки нет — не пиши поле вообще (пустая строка тоже допустима, но
  засоряет файл).
- В `youtube` — канал автора. Видео о моде пишутся в `[description] videos`.

---

## 5. `[description]`

| Поле | Тип | Обязательно | Что это |
| --- | --- | --- | --- |
| `en` | строка | да | Английское описание. |
| `ru` | строка | нет | Русское описание. |
| `videos` | массив строк | нет | Ссылки на YouTube. |

- `en` никогда не бывает пустым. Он же показывается, если русского нет.
- Текст — обычная строка, без переносов. 1–3 предложения: что мод делает и
  зачем он нужен.
- Без Markdown и HTML: звёздочки и теги покажутся как текст.
- Ссылки в текст не вставляй: видео идут в `videos`, соцсети — в `[credits]`.
- `videos` — только `youtube.com/watch`, `youtu.be` и `youtube.com/shorts`.
  Каждая ссылка даёт превью с плеером в карточке.

## 6. `[download.partN]`

Каждый том архива — отдельная секция. Номер задаёт порядок склейки.

```toml
[download.part1]
url = "https://.../Mod.7z.001"
size = 1939865600
sha256 = "3E3FDF871364CF3367182A9D1B7B3C4C498111C1C1FE32DC02007BEB44859F52"
```

| Поле | Тип | Обязательно | Что это |
| --- | --- | --- | --- |
| `url` | строка | да | Прямая ссылка на файл. |
| `size` | число | да | Размер в байтах. |
| `sha256` | строка | да | SHA-256 файла, 64 шестнадцатеричных символа. |

Правила:

- Один архив — одна секция `[download.part1]`.
- Несколько томов — `part1`, `part2`, `part3` и так далее. Тома склеиваются в
  порядке номера, а не по алфавиту: `part10` идёт после `part9`.
- Максимум 9 томов.
- Номер в имени секции и номер в имени файла не обязаны совпадать с `.001`,
  но обычно совпадают.
- `url` — прямая ссылка на файл, а не на страницу релиза.
- `size` — точный размер в байтах.
- `sha256` — можно в верхнем или нижнем регистре, сравнение без учёта регистра.
- Мод ещё не готов? Не пиши секцию `[download]` вообще: карточка покажет
  «Скоро».
- Если файл на GitHub, имя архива должно совпадать с `id`:
  `Releases/download/<id>/<id>.7z.001`.

## 7. `[files]`

Пути пишутся от корня сборки игры. Слэши удваиваются (`\\`) либо используй
одинарные кавычки.

| Поле | Тип | Что это |
| --- | --- | --- |
| `config` | строка | Путь к конфигу мода от корня сборки. Один файл. |
| `affected_files` | массив строк | Файлы, которые мод заменяет. Нужны для проверки конфликтов. |
| `installed` | массив таблиц | Только для `type = "Build"`: моды, уже входящие в сборку. |
| `dependencies` | массив таблиц | Моды, без которых этот не работает. |

### `config`

```toml
config = "BepInEx\\config\\BepInEx.cfg"
# или
config = 'BepInEx\config\BepInEx.cfg'
```

- Один файл. Если конфигов несколько, укажи основной.
- Пусто или поля нет — редактор конфигов не откроется для этого мода.

### `affected_files`

```toml
affected_files = [
    "PoseMod\\Modules\\pmcore00.dll",
    "YandereSimulator_Data\\Managed\\Assembly-CSharp.dll",
]
```

- Только файлы, которые мод **заменяет** или **удаляет**. Новые файлы сюда не
  пишутся.
- Нужны для предупреждения «этот файл уже занят другим модом».

### `installed`

```toml
installed = [
    { id = "posemod", v = "5" },
    { id = "bee" },
]
```

- Смысл имеет только у сборок (`type = "Build"`).
- `v` можно не писать — тогда показывается просто название.
- Это **не** зависимости: это состав сборки, «что уже стоит внутри».

### `dependencies`

```toml
dependencies = [
    { id = "posemod", v = "5" },
    { id = "bee", optional = true },
]
```

- `id` — идентификатор другого мода из каталога.
- `v` — версия. Можно не писать: подберётся совместимая со сборкой.
- `optional = true` — мод работает и без зависимости. Можно не писать.

## 8. README, changelog и изображения

### README.md

- Лежит в папке мода, рядом с папками версий.
- Показывается в карточке под обычным описанием, если файл существует.
- Markdown допустим, но без внешних картинок и скриптов.

### changelog.md

- Там же, рядом с `README.md`.
- Показывается в свёрнутом блоке «Изменения».
- Формат свободный, но по одной версии на раздел:

  ```markdown
  ## 1.0.0
  - Добавлена рождественская вечеринка.
  - Исправлены пропадающие диалоги.
  ```

### Изображения (в папке версии)

| Файл | Что это |
| --- | --- |
| `1.webp` | Обложка. |
| `2.webp`, `3.webp`, … | Остальные скриншоты. |
| `.gif` | Анимированный скриншот. |
| `ico.webp` | Квадратная иконка для угла обложки. Также `icon.webp` или `ico.png`. |

- Нумерация естественная: `2.webp` раньше `10.webp`.
- Скриншоты — только `webp` или `gif`. `png` годится только для иконки.
- Если скриншотов нет, обложкой станет превью первого видео.

## 9. `index.toml`

Список файлов каталога для лаунчера и веб-страницы. **Пишется автоматикой**,
руками не редактируется.

```toml
files = [
    "build/ChristmasPartyMod/1.0.0/info.toml",
    "build/ChristmasPartyMod/1.0.0/1.webp",
]
```

## 10. Частые ошибки

| Ошибка | Симптом | Как исправить |
| --- | --- | --- |
| `config = "BepInEx\config\..."` | `invalid escape sequence` | Удвой слэши или используй `'...'`. |
| `size = "..."` | ошибка типа | Размер числом, без кавычек. |
| `size = 1.9 GB` | мусор после числа | Только байты: `1939865600`. |
| `tags = [Christmas]` | невалидный TOML | Каждый тег в кавычках, нижний регистр. |
| `id = "My Mod"` | мод не находится по зависимостям | Без пробелов: `MyMod`. |
| Две секции `[info]` | ошибка разбора | Каждая секция в файле один раз. |
| Перенос внутри `{ ... }` | ошибка разбора | Inline-таблица — одной строкой. |
| `[download.part1]` и `[download.part2]` в обратном порядке | тома склеиваются неверно | Сортировка идёт по номеру, но держи порядок по возрастанию. |
| `part10` при 10 томах | не поддерживается | Максимум 9 томов. |
| Пустой `en` | карточка без описания | Английское описание обязательно. |
| `type = "build"` | мод попадёт не в тот раздел | Точно `Build`. |
| `game_versions = ">= U17"` | совместимость не распознана | Без пробела: `>=U17`. |

## 11. Шаблон для копирования

```toml
[info]
id = ""
name = ""
author = ""
type = "Mod"
game_versions = ""
mod_version = "1.0.0"
tags = []

[credits]

[description]
en = ""
ru = ""

[download.part1]
url = ""
size = 0
sha256 = ""

[files]
config = ""
affected_files = []
dependencies = []
```

## 12. Чек-лист перед коммитом

- [ ] Файл называется `info.toml` и лежит в папке версии.
- [ ] `id` совпадает с именем архива и не содержит пробелов.
- [ ] `type` — одно значение из списка, с большой буквы.
- [ ] `en` заполнен.
- [ ] `mod_version` совпадает с папкой версии или осознанно отличается.
- [ ] Все пути с `\\` или в одинарных кавычках.
- [ ] `size` и `sha256` заполнены для каждого тома.
- [ ] Теги в нижнем регистре, не больше пяти.
- [ ] Файл открывается без ошибок: скопируй текст в любой TOML-валидатор.
- [ ] `README.md` и `changelog.md` обновлены, если менялось содержимое.
